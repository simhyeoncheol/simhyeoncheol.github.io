프로젝트 소개

디데이, Apple 캘린더 일정, 미리 알림을 메뉴바 앱과 데스크톱 위젯 11종으로 제공하는 macOS 네이티브 앱입니다. App Intents 기반 인터랙티브 위젯으로 앱을 열지 않고 일정 조회와 할 일 완료 처리가 가능합니다.

주요 구현 기능

01

설정 가능한 인터랙티브 위젯

App Intents(SelectDDayIntent)로 인스턴스별 디데이·분류·잠금을 구성하고, 스와이프 제스처가 없는 위젯에서 ShiftDDayIntent 버튼으로 페이지를 순환합니다. WidgetKit이 인스턴스 ID를 제공하지 않아 구성값과 크기로 인스턴스 키를 생성합니다.

02

잠금 위젯과 생체 인증

위젯은 인증 UI를 띄울 수 없어 dday://unlock 딥링크로 앱에 위임하고, LAContext(Touch ID · 암호) 성공 시 해당 위젯만 30초간 해제합니다. 재잠금 시점은 타임라인 엔트리로 미리 스케줄링합니다.

03

위젯에서 EventKit 쓰기

ToggleTodoIntent가 캐시를 먼저 갱신하는 낙관적 업데이트 후 EKReminder를 저장하고, 위젯 프로세스에서 쓰기가 불가능하면 대기 큐와 DistributedNotificationCenter로 앱에 위임합니다.

기술적 과제와 해결

한국 공휴일·대체공휴일 규칙 엔진

과제달력과 위젯에 한국 공휴일과 대체공휴일을 정확히 표시해야 했습니다.

분석대체공휴일은 공휴일별로 규칙이 다릅니다. 설·추석은 연휴가 일요일 또는 다른 공휴일과 겹칠 때만 적용되고 토요일은 제외되며, 삼일절·어린이날·광복절 등은 토·일 모두 대상이고, 신정·현충일은 비대상입니다. 대체일이 다시 공휴일이나 주말과 겹치면 연쇄적으로 밀립니다. Foundation .chinese 달력은 2027·2028년 설날을 한국 음력과 하루 다르게 계산합니다.

해결공휴일 테이블에 대체 대상 여부를 선언적으로 두고, nextFreeWeekday로 주말·공휴일이 아닌 첫 날을 찾습니다. 설·추석은 3일 연휴 단위로 판정하고, 설날 오차는 보정 테이블로 처리했습니다. 음력 변환은 월별 탐색 구간을 좁혀 전체 순회를 피하고, 연도별 결과는 NSLock으로 보호한 캐시에 두어 앱 시작 시 전년·당해·익년을 백그라운드에서 warm-up합니다.

성과2026년 삼일절·부처님오신날·광복절·개천절 대체, 추석 토요일 비대상, 2025년 추석·개천절 중첩 등 경계 케이스를 테스트로 고정했고, 연간 계산 20ms 미만 성능 테스트를 두었습니다.

주간 타임그리드의 겹치는 일정 레이아웃

과제주간 보기에서 하루의 일정을 시간축에 맞춰 배치해야 했습니다.

분석시간이 겹치는 일정은 같은 열에서 서로 가리고, 자정을 넘기거나 매우 짧은 일정은 셀 밖으로 나가거나 보이지 않습니다.

해결일정을 당일 범위로 클리핑하고 최소 높이를 15분으로 둡니다. 시작 시각 오름차순(동률이면 종료 늦은 순)으로 정렬한 뒤 겹침이 이어지는 일정을 클러스터로 묶고, 클러스터 안에서는 그리디하게 비어 있는 첫 열에 배정합니다. 클러스터가 닫히면 열 개수를 각 일정에 반영하고, 겹침 없는 일정은 전체 폭을 사용합니다.

성과겹침 일정의 열 분리, 단독 일정의 전체 폭 배치를 테스트로 검증했습니다.

EventKit 조회 제한과 반복 일정 회차 식별

과제Apple 캘린더 일정을 장기간 표시하고 앱 안에서 수정·삭제를 지원해야 했습니다.

분석EventKit은 단일 조회 범위가 4년으로 제한됩니다. 반복 일정은 모든 회차가 같은 eventIdentifier를 가져 SwiftUI 목록 identity가 충돌하고 회차 단위 수정이 어렵습니다. 편집 저장 과정에서 외부 앱이 설정한 알림이 덮어써질 위험도 있었습니다.

해결조회를 1년 단위로 분할하고 경계 중복은 Set으로 제거합니다. 회차 identity를 eventIdentifier + 시작 시각으로 정의하고, 저장·삭제 시 .thisEvent / .futureEvents span을 선택하게 했습니다. 알림은 변경된 경우에만 갱신하고, 범위 조회는 fetch token으로 늦게 도착한 stale 응답을 폐기합니다.

앱-위젯 프로세스 간 데이터 공유

과제위젯 11종이 앱 데이터를 표시하고, 위젯에서 할 일 완료 같은 쓰기 동작도 지원해야 했습니다.

분석위젯 확장은 별도 프로세스라 앱 메모리에 접근할 수 없고, 갱신 시점도 WidgetKit 타임라인으로 직접 관리해야 합니다. 위젯 프로세스의 캘린더 권한 상태도 앱과 다를 수 있습니다.

해결App Group UserDefaults에 JSON으로 공유하고, 쓰기는 400ms 디바운스로 묶어 reloadAllTimelines()를 호출합니다. 위젯에 권한이 있으면 EventKit을 직접 조회하고, 없으면 앱이 기록한 캐시로 fallback합니다. 위젯의 할 일 토글은 캐시를 먼저 갱신하는 낙관적 업데이트 후 EKReminder를 저장하고, 실패 시 대기 큐와 DistributedNotificationCenter로 앱이 이어 처리합니다.

메뉴바 앱의 잠금 상태 전이와 창 생명주기

과제앱 잠금(Touch ID)을 지원하는 메뉴바 앱으로, 로그인 시 자동 실행됩니다.

분석메뉴바 패널은 앱을 활성화하지 않을 수 있어 didResignActive만으로는 재잠금이 보장되지 않고, 패널에서 인증 UI를 띄우면 패널이 닫힙니다. 로그인 항목 실행이나 URL scheme 호출 시에는 창이 열리면 안 되는데, SwiftUI openWindow는 뷰 컨텍스트에서만 얻을 수 있어 AppKit 경로에서 창을 제어할 수 없었습니다.

해결패널 onDisappear에서 비활성 상태면 잠그고, 인증 중에는 재잠금을 건너뛰며, 슬립·화면 꺼짐·세션 전환 시 앱과 위젯의 해제 상태를 모두 초기화합니다. 로그인 항목은 SMAppService.mainApp으로 등록하고 Apple Event(keyAELaunchedAsLogInItem)로 로그인 실행을 감지해 창을 닫습니다. .handlesExternalEvents(matching: [])로 URL 호출 시 창 생성을 막고, 라우터에 openWindow를 주입해 AppKit에서도 창을 열 수 있게 했습니다.

비결정적 데이터 소스의 안정 정렬

과제할 일 목록에서 완료 처리해도 항목 위치가 유지돼야 했습니다.

분석EventKit의 반환 순서는 비결정적이고, 완료 여부를 정렬 키에 포함하면 토글 시 항목이 재배치됩니다.

해결마감일 → 우선순위 → 제목(localizedStandardCompare) → ID로 결정적 정렬 키를 정의하고 완료 여부는 키에서 제외했습니다. 당일 완료 항목은 원위치에 취소선으로 유지하고, 위젯에서는 후순위로 배치합니다.

성과입력 순서 셔플·완료 토글에도 동일 순서가 유지되는지 테스트 2개로 검증했습니다.
