영상의학 · PACS 연동

병원 OCS와 PACS · 모달리티 장비 사이의 연동 테이블을 추적해 판독결과 누락과 상태 불일치를 해결했습니다.

MSSQLOracleOCS 클라이언트

OCS ↔ PACS 데이터 흐름: 처방 → 판독결과 테이블 → 워크리스트 → 큐 → PACS

프로젝트 소개

병원 42곳의 OCS/EMR 유지보수 요청 3,300여 건 중 영상의학 · PACS 관련 100건(병원 28곳)을 처리했습니다. 처방이 판독결과 테이블, 워크리스트, 큐 테이블을 거쳐 PACS로 가고 판독결과가 다시 OCS로 돌아오는 경로를 단계별로 조회해 문제가 OCS 쪽인지 PACS · 장비 업체 쪽인지 근거를 갖춰 판정하고, OCS 쪽 원인은 저장 프로시저 · 트리거 · 리포트를 직접 수정했습니다.

주요 구현 기능

01

연동 테이블 단계별 원인 판정

처방 → 판독결과 테이블 → 워크리스트 → 큐 테이블 순으로 조회해 OCS 데이터가 정상인지 확인하고, PACS 결과 미전송 · 브로커 미기동 · 장비 모달리티 미등록 등 업체 측 원인 7건(병원 6곳)을 근거와 함께 이관했습니다.

02

판독결과 후처리

판독결과 테이블 트리거로 CVR(이상결과)을 OCS에 자동 등록하고, 판독소견서를 고시 기재 항목(검사일시 · 판독일시)에 맞춰 개편했습니다.

03

영상 조회 · 접수 프로시저 보완

당일내원 · PACS 바로전달 · 포터블 · 내시경 처방이 결과 조회에서 빠지던 조건과 형변환 오버플로를 수정했습니다(TRY_CONVERT, DB 오류 로그 추적).

04

영상 검사예약

예약 삭제 프로시저가 환자번호 0일 때 그날 예약을 모두 지우던 문제를 시간 조건 복원으로 수정하고, 원인 추적용 트리거를 설치했습니다.

OCS ↔ PACS 데이터 흐름

OCS영상 처방

외래 · 입원 처방과 처방 상세 테이블. 변경 이력은 트리거 이력 테이블에 남음

OCS판독결과 테이블

검사 단위 행 생성: 검사번호 · 상태 · 판독결과 · 판독의

OCS ↔ 장비워크리스트

검사번호 · 환자ID · 검사코드. 모달리티 장비가 조회

브로커큐 테이블

검사번호 키 · 상태 · 처방의 · 모달리티, 판독문 전달

PACS촬영 · 판독

판독이 끝나면 큐 상태 반영 프로시저가 판독결과 테이블과 처방 상태를 갱신

수가코드에 PACS 바로전달이 설정된 처방은 영상의학과 접수 단계 없이 PACS로 넘어갑니다. 반영된 판독결과는 영상결과 조회, 판독소견서(Rexpert), 진료의뢰서, 대기안내 PDP, CVR 등록에서 사용됩니다.

주요 사례 (상황 → 원인 → 조치 → 결과)

판독문의 CVR(이상결과)을 OCS에 자동 등록

상황판독의가 CVR을 전달하려면 PACS에서 판독한 뒤 OCS 검사 입력 화면에서 같은 내용을 다시 입력해야 했습니다.

원인PACS 판독결과와 OCS CVR 사이에 연계 경로가 없었습니다.

조치판독결과 테이블의 INSTEAD OF UPDATE 트리거에 분기를 추가해, 판독결과에 "CVR RESULT" 문구가 있으면 CVR 등록 프로시저를 호출하도록 개발했습니다. 이후 "CVR RESULT" 앞의 판독문만 판독결과에 남도록 보완했습니다.

결과테스트를 거쳐 실서버에 반영했습니다. 판독의는 PACS 판독문만 작성하면 CVR이 OCS에 등록됩니다.

PACS에 처방의 이름이 표시되지 않음

상황PACS 화면에 처방의 성명이 나오지 않았고, PACS 업체는 "사번 앞에 0이 하나 더 붙어 있다"고 회신했습니다.

원인워크리스트 · 큐 생성 프로시저가 다른 병원 기준으로 만들어져 사번 앞에 0을 붙이고 있었습니다.

조치생성 프로시저 2개에서 0을 붙이는 로직을 제거하고, 큐 테이블에서 사번이 0으로 시작하는 기존 데이터를 SUBSTRING으로 일괄 보정했습니다.

결과프로시저 수정과 기존 데이터 보정을 함께 완료했습니다.

"판독했는데 결과가 안 넘어온다"

상황판독이나 촬영이 끝났는데 OCS에 상태와 결과가 반영되지 않거나, 장비 워크리스트에 처방이 보이지 않는다는 문의가 병원 6곳에서 7건 들어왔습니다.

원인처방 → 판독결과 테이블 → 워크리스트 → 판독문 전달 테이블 → 큐 테이블 순으로 조회해 보니 OCS 데이터는 정상이었고, PACS 업체의 결과 미전송, PACS 브로커 미기동, 특정 장비에서만 조회되지 않는 장비 설정, 처방명칭 차이로 PACS 이벤트가 동작하지 않은 것 등이 원인이었습니다.

조치단계별 조회 결과를 근거로 원인을 정리해 PACS · 장비 업체로 이관하도록 안내했습니다.

결과7건 모두 연동 단계별 근거로 원인 위치를 판정했습니다.

전일자에 매칭한 촬영 · 판독 상태가 반영되지 않음

상황응급실 · 수술실처럼 워크리스트를 쓰지 않고 촬영한 뒤 영상의학과가 나중에 매칭하면, OCS 처방이 "접수" 상태에 머물렀습니다.

원인큐 상태 반영이 당일분만 자동으로 처리되고 있었습니다.

조치큐 테이블과 판독결과 테이블을 검사번호로 조인해 미반영 건을 찾고, 상태 반영 프로시저 2개를 해당 일자로 실행했습니다. 병원에는 당일 매칭으로 업무를 바꾸도록 안내했습니다.

결과같은 유형 4건의 상태를 바로잡았습니다.

판독문 이상값으로 소견서 · 의뢰서 · 사본이 깨짐

상황판독소견서에 "." 하나만 출력되거나, 진료의뢰서에 판독결과가 나오지 않거나, 의무기록사본 XML이 깨지는 문제가 병원 3곳에서 있었습니다.

원인외부 판독의가 판독결과에 "..."만 입력했거나, 줄바꿈 문자만 들어 있었거나, 판독문 앞에 ESC 제어문자(0x1B)가 들어가 있었습니다.

조치소견서 Rexpert 쿼리는 "."을 제거한 값이 비어 있으면 다른 판독결과 컬럼을 쓰도록, 진료의뢰서 결과 조회 프로시저는 CR/LF를 제거한 뒤 빈 값을 검사하도록 수정했고, 제어문자가 들어간 데이터는 정정했습니다.

결과3건 모두 수정 · 정정을 완료했습니다.

외래 → 입원 전환 시 판독 상태 불일치

상황판독이 끝났는데 초음파 대기안내(PDP)에서 환자가 빠지지 않거나, 입원간호와 영상의학과의 검사 상태가 서로 달랐습니다.

원인외래 처방이 입원으로 넘어가면 결과값이 외래 처방에만 갱신되고 입원 처방은 갱신되지 않았습니다.

조치입원 처방과 처방 상세의 상태값을 보정하고, PDP 조회 프로시저를 입원 전환 처방까지 고려하도록 수정했습니다.

결과같은 유형 4건(병원 3곳)을 처리했습니다.

당일내원 · 바로전달 · 내시경 처방이 결과 조회에서 빠짐

상황당일내원 초음파의 영상결과가 보이지 않아 사본 출력이 안 되고, 내시경 처방이 영상결과 팝업에 나오지 않았으며, 포터블 처방 표시가 부족했습니다.

원인조회 프로시저가 당일내원 · PACS 바로전달 처방을 제외하고 있었고, 부서 코드 하나를 초음파로 가정해 제외했는데 해당 병원에서는 그 코드가 내시경실이었습니다.

조치의무기록 요청 · 영상결과 조회 프로시저 3개에 당일내원과 PACS 바로전달 조건을 추가하고, 부서 코드 제외 조건을 제거했으며, 접수 조회 프로시저에 포터블 조건을 넣었습니다.

결과병원 3곳의 조회 프로시저를 수정했습니다.

이중차트 합철 후 워크리스트에 옛 환자번호가 남음

상황중복 등록된 환자 차트를 하나로 합친 뒤에도 워크리스트 테이블에는 옛 환자번호가 남아 장비에서 잘못 조회됐습니다.

원인합철 프로시저의 갱신 대상 목록에 워크리스트 테이블의 환자ID 컬럼이 빠져 있었습니다.

조치급한 건은 데이터를 먼저 이관하고, 합철 프로시저에 해당 컬럼 갱신 조건을 추가했습니다.

결과이후 합철하면 워크리스트 환자ID도 함께 바뀝니다.
