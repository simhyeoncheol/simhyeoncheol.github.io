프로젝트 소개

(주)더바디채널 회원이 심박밴드(BLE), Apple Watch, Galaxy Watch로 운동하면 심박·칼로리·경로를 측정하고, 기록을 피드·랭킹·출석 챌린지로 연결하는 운동 앱입니다. 폰 앱, 워치 앱(watchOS · Wear OS), 백엔드(Node.js · MySQL)를 담당했습니다.

주요 구현 기능

01

워치 측정과 폰 동기화

HKLiveWorkoutBuilder로 심박·칼로리·거리를 시스템 측정값으로 받고, 폰 ↔ 워치는 매초 값 대신 기준 시각만 전송합니다(상태는 applicationContext, 이벤트는 transferUserInfo, 좌표는 배치 전송). 앱 프로세스가 종료돼도 진행 중 세션을 복구합니다.

02

심박 기반 칼로리와 측정 엔진

칼로리를 Keytel(2005) 심박 회귀식 구간 적산으로 교체했습니다(예: 70kg · 30세 · 심박 140 · 30분 171 → 약 381kcal). RunningEngine을 순수 모듈로 분리하고, 걸음 신호 기반 자동 일시정지를 녹화 트랙 리플레이로 검증했습니다.

03

헬스 플랫폼 통합과 백엔드 재설계

HealthKit(경로·걸음·심박)과 Samsung Health Data SDK(심박 로그)를 공통 스키마로 정규화했습니다. 신규 DB 스키마 설계와 데이터 마이그레이션, 랭킹 증분 집계 배치, ERP 출결 기반 30일 출석 챌린지(보상 이중 지급 방지)를 구현했습니다.

기술적 과제와 해결

Apple 피트니스와 동일한 구간(split) 기록

과제사용자가 Apple 피트니스와 기록을 비교하기 때문에 1km 구간 기록을 초 단위까지 일치시켜야 했습니다.

기존좌표로 구간을 직접 계산했고, HealthKit의 workoutEvents만 읽어 iOS 17 이후 일시정지가 0건으로 집계됐습니다. 시각은 초 단위로 절삭해 전달했습니다.

분석좌표 기반 자체 계산은 Apple 결과와 구간마다 수 초씩 오차가 있어, HealthKit이 제공하는 .segment 이벤트를 원본으로 쓰기로 했습니다. 다만 iOS 17부터 일시정지 이벤트가 workoutActivities 쪽에 붙고, km·마일 segment가 구분 없이 섞여 오며, 초 단위로 절삭하면 구간마다 최대 1초 오차가 누적됩니다.

해결iOS 17 activity 이벤트와 activity 사이 간격까지 수집해 밀리초 ISO 문자열로 브리지에 넘기고, 구간 경계가 이어지는 체인(허용 오차 3초)을 구성해 총거리에 맞는 체인(km)을 선택합니다. 일시정지 구간을 차감하고 반올림 전 값으로 페이스를 계산하며, segment가 없는 기록은 거리 샘플 → 좌표 순으로 fallback합니다.

성과실기기 5km 러닝에서 6:10 / 6:26 / 6:57 / 7:00 / 8:06 / 8:15로 Apple과 전 구간 일치했습니다.

GPX 리플레이 기반 거리 측정 정확도 개선

과제실외 테스트를 반복할 수 없어 실제 코스 좌표를 에뮬레이터에 재생(adb emu geo fix)하는 재현 환경을 먼저 구축했습니다.

기존거리 계산이 벽시계(Location.time) 기준이었고, 4초 이상 좌표 공백을 모두 신호 손실로 보고 세그먼트를 끊었습니다. 실외 측정을 재현할 환경이 없었습니다.

분석990.6m 코스가 440m(-56%)로 측정됐고 원인이 세 가지 겹쳐 있었습니다. Location.time은 벽시계라 정지·역행 시 dt <= 0으로 거리가 누락되고, 세그먼트를 새로 열 때 미확정 거리를 폐기했으며, Fused Provider가 1초 요청에도 2~5초 간격으로 응답하는데 4초 초과 간격을 일괄 신호 손실로 처리했습니다.

해결시간 기준을 단조 시계(elapsedRealtimeNanos)로 바꾸고, 세그먼트 분할 전에 대기 거리를 커밋(_commitPending)하도록 했습니다. 30초 이내 공백은 속도 검증 후 브리징하고 브리징 시간은 별도 집계하며, 종목별 속도 임계값을 적용했습니다. 리플레이 스크립트와 ndjson 픽스처 6종(터널 60초, 5분 정지 등)으로 원인을 분리했습니다.

성과오차 -56% → -7.1%(920m), 세그먼트 17 → 3. 에뮬레이터 좌표 기준이며 실외 필드 테스트는 진행할 예정입니다.

사내 회원 시스템과의 계정 통합

과제FitSignal 계정을 바디채널 회원 시스템으로 통합해야 했습니다.

기존이름·전화·비밀번호를 서비스 DB에 복제했고, 비밀번호는 평문이었습니다. DB 계층은 mysql@2 단일 연결이라 연결이 끊기면 서버는 살아 있는 채로 모든 쿼리가 실패했습니다.

분석회원 정보를 복제하면 원본과 사본의 정합성 문제가 생기고 비밀번호도 이중 관리됩니다. 원본 회원 DB에는 쓰기 권한이 없었고, 회원 API 명세도 없었습니다. 기존 드라이버(mysql@2)는 MySQL 8 기본 인증 플러그인(caching_sha2_password)을 지원하지 않았습니다.

해결회원 원본을 단일 원천(SSOT)으로 두고 FitSignal에는 회원 키와 서비스 전용 속성만 가진 위성 테이블을 두어, 조회 시 원본 우선으로 병합(COALESCE)합니다. 회원앱 웹 번들 JS 72개를 역분석해 약관·인증번호·중복 확인·가입 API를 문서화하고 연동했습니다. DB 계층은 mysql2 커넥션 풀과 prepared statement로 교체하고, 응답 키는 SQL alias로 유지해 클라이언트 변경 없이 스키마를 전환했습니다.

성과API 흐름 테스트 72개, 예외 테스트 43개 실패 0건.

워치 가용성 판정 로직

과제실내 운동은 심박 측정 기기가 필수라 세션 시작 전에 워치 사용 가능 여부를 판정해야 했습니다.

분석isReachable은 워치 전원 상태가 아니라 워치 앱의 foreground 여부를 의미하고, 워치가 꺼져도 isPaired·isWatchAppInstalled는 true로 남아 상태를 구분할 수 없었습니다. 진단이 불확실한 값으로 기능을 막으면 UI 판정과 실제 시작 경로가 어긋납니다.

해결확정 가능한 조건(미페어링, 앱 미설치)만 사전 차단하고, 나머지는 HKHealthStore.startWatchApp으로 실제 기동을 시도한 뒤 9초 타임아웃 시 실외는 폰 GPS로 fallback, 실내는 안내 후 중단합니다. UI 잠금과 시작 경로가 같은 판정 함수를 공유하게 했습니다.

성과watchReadiness.test.js로 판정 규칙을 회귀 테스트화했습니다.

불규칙 샘플링 심박 데이터의 통계 정합성

과제심박밴드(BLE), Apple Watch, Galaxy Watch의 심박으로 평균 심박과 존별 체류 시간을 제공해야 했습니다.

기존평균 심박은 산술평균, 존 체류는 측정 횟수로 집계했고 컬럼명만 hr_zone_*_sec였습니다. 끊긴 구간은 30초까지만 세어 존 합계가 운동 시간보다 6분 짧았습니다.

분석BLE notify 간격이 불규칙(2초에 4회 → 40초 공백)해 산술평균은 샘플 밀도가 높은 구간에 편향됩니다. 존 체류를 샘플 수로 집계하면 시간으로 환산할 수 없고, 기존 데이터(횟수 기반)와 하위 호환도 유지해야 했습니다.

해결각 샘플이 다음 샘플까지를 대표하는 시간 가중 평균(샘플당 상한 600초)으로 바꾸고, 20초가 지난 값은 stale로 처리해 표시하지 않습니다. 존은 실제 초 단위로 적산하고, 비율의 분모를 존 합계로 바꿔 구·신 데이터가 섞여도 비율이 일관되게 했습니다.

성과heartRateStats.test.js 작성, 당시 Jest 383 tests 통과.

랭킹 증분 집계 배치와 순위 정합성

과제월별 랭킹을 지표 5종으로 제공하고, 상위권 밖 사용자에게도 본인 순위를 보여 줘야 했습니다.

기존랭킹 요청마다 원본 테이블을 풀스캔했고, 화면에서 지표 칩 5개를 넘기면 같은 집계가 5번 실행됐습니다.

분석요청마다 원본 테이블을 풀스캔하는 구조였고, 정수로 저장된 집계값과 원본 실시간 값을 섞어 비교하면 반올림 차이(158.6 → 159)로 순위가 어긋납니다. 배치가 멈춰도 감지할 수단이 없었습니다.

해결파생 테이블 ranking_monthly를 두고 MySQL EVENT로 5분 증분 집계와 매일 04시 전체 재계산을 돌립니다. 회원·월 단위로 DELETE 후 재생성해 수정·삭제를 반영하고, ranking_rollup_log로 실행 여부와 처리 건수를 기록합니다. 본인 순위는 원본 기준으로 계산하되 본인 집계 행은 비교 대상에서 제외하고, 클라이언트는 마감 월 무기한·당월 60초 TTL로 캐싱하며 업로드 시 캐시를 무효화합니다.

성과목록과 본인 순위 카드 간 불일치를 해소했습니다.

경로 비공개 정책과 위치 메타데이터 보호

과제운동 경로는 거주지와 생활 반경을 드러낼 수 있어 게시글 단위로 지도 비공개를 지원했습니다.

분석하나의 운동을 여러 게시글에 연결하고 일부만 비공개로 설정할 수 있어, 운동 단위로는 접근 제어를 판정할 수 없습니다. 좌표를 마스킹해도 고도·타임스탬프가 남으면 지형 대조로 경로를 추정하거나 활동 시간대를 알 수 있습니다.

해결공개 여부는 조회 중인 게시글 컨텍스트(feedId)로 판정하고, 컨텍스트가 없으면 연결된 공개 게시글이 모두 비공개일 때 마스킹합니다(MIN(map_private)). 마스킹 시 타임스탬프·고도·정확도와 시작 지점명을 제거하고, 목록 API에도 동일한 공개 범위 조건을 적용했습니다.

비신뢰 채널 위의 세션 종료 프로토콜

과제워치에서 종료한 운동이 폰 UI와 서버에 확실히 반영돼야 했습니다.

분석sendMessage는 수신 측이 reachable일 때만 전달되는 비보장 채널이고, 업로드 실패와 무관하게 UI 상태는 종료돼야 합니다. Wear OS에서는 onDestroy에서 종료 코루틴이 두 디스패처로 중복 실행돼 서로 cancel되면서 운동 세션이 시스템에 남을 수 있었습니다.

해결종료 명령은 워치의 ACK까지 재전송하고, 저장과 종료 신호를 분리했습니다. 상태 정리는 finally로 옮겨 업로드 결과와 무관하게 실행되게 했고, Wear OS 종료 작업은 단일 launch로 바꿨습니다. 폰과 워치가 최소 운동 시간 기준 상수를 공유하게 했습니다.

성과종료 재전송 로직을 sendStopWorkout.test.js로 테스트했습니다.
